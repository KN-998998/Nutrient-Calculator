# 营养素计算工具

面向学生餐 SOP 的可审计营养计算服务。网页读取 A–E 餐主 SOP 页，计算小学和中学两套营养值，并按圣类斯 15 列上架模板导出。

## 计算口径

- SOP 克重：`安士 × 28.35`（现有工作簿已经生成克重列，本工具读取克重列）
- 可食重量：`下单克重 × 可食率`
- 单项营养：`可食重量 ÷ 100 × 每100g营养值 × 营养保留率`
- 套餐营养：所有食材贡献求和
- 估计熟重：`可食重量 × 熟重得率`
- 每100g成品：`套餐总营养 ÷ 成品熟重 × 100`
- 宏量能量校验：`蛋白质×4 + 总脂肪×9 + 可利用碳水×4`

营养数据库的所有营养指标均须填写为“每100克可食用部分”。第一版不虚构营养保留率，默认值为 1.0；如有经过确认的因子，再写入食材或配方记录。计算过程保留未四舍五入值，仅在导出展示时舍入。暂行缺项及按件估重规则见[计算规则](calculation_rules.md)：未报告的营养项暂按 0 参与计算但标记复核；克重估算仅在明确件数和已登记单重时触发。

## 快速开始

```powershell
python -m pip install -e .
python -m web_app.app
```

打开 `http://127.0.0.1:8300`，上传 SOP，检查营养值及缺失食材后导出。

## 输入与输出

- 输入工作簿默认只读取可见的标准 A–E 餐配料 SOP 工作表；不读取隐藏参考页、菜单排期页、官方营养资料页或带学校附注的重复专页。
- SOP 同时包含小学和中学克重时，两个学段分别计算，并分别输出到「小学标准」「中学标准」两个工作表。
- 输出沿用 `data/templates/聖類斯上架模版.xlsx` 的 15 列表头和行格式；A 列商品名称采用「餐别(日)菜名」（如 `A(1)馬蹄蒸肉餅配飯(菜心苗)`），E 列填八项合并营养详情，其余列留空。
- `passed` 和 `review` 菜品可导出；`review` 的估算、替代来源及缺项提示在网页复核明细中显示，导出模板只填 A/E 两列。存在未匹配食材或 SOP 解析缺项的 `incomplete` 菜品整行不进入上架表。
- 导出仅自动填写商品名称和商品详情，其余分类、图片、规格、库存及过敏源字段留空，供营养师按上架要求维护。

## ECS 部署

本项目以阿里云 ECS 上的网页服务为唯一运行交付方式；不发布 Windows/macOS 桌面程序或 EXE。GitHub Actions 中原有的双平台打包发布流程已移除。

```powershell
gunicorn --workers 1 --threads 4 --bind 0.0.0.0:8300 wsgi:app
```

部署时保留 `data/templates/`、`data/` 营养数据库和 `web_app/templates/` 页面资源。SQLite 历史记录当前按单机方式使用。

网页部署监听 `0.0.0.0:8300` 时，应在 ECS 安全组配置对应入站规则，并限制来源范围或使用 HTTPS 反向代理。

## 营养数据库字段

- `ingredient_code`：优先匹配现有 SOP 编码
- `ingredient_name`、`aliases`：编码缺失时的标准名及别名匹配
- 九项营养值：每100克可食用部分
- `edible_fraction`：可食率，0–1
- `yield_factor`：熟重得率，可因吸水而大于1
- `retention_factor`：初版统一营养保留率，0–1
- `source`、`source_food_id`：香港食安中心、供应商标签或实验室的可追溯来源
- `data/ingredient_nutrient_corrections.csv`：按 SOP 食材名优先应用的逐项修订档案；空白营养项表示来源未报告，计算暂按 0 并保留复核状态，`block` 项会阻止不确定的旧匹配

2026 年 9 月复核工作簿的 291 个名称已逐项对齐名称修订层：其中 290 个是实际食材名，另 1 个「1個」是件数栏（解析器按「健康飯卷」115g/個 计入，不以「1個」查营养）。修订层现有 295 个名称档案；合并按别名/分项解析后的实际使用名，共 293 个食材名，全部具备八项数值，未匹配 0、必需营养项缺项 0，290 道菜品（小学 156、中学 134）均为「八项完整、待营养师复核」。只剩「1個」保留 `block`，用于阻止纯数量单元被误配，不参与食材覆盖统计。每项的来源、日期、适用限制、均值品牌数和估算说明保存在修订记录与复核工作簿「食材营养值」页中。

## 输出状态

- `passed`：食材全部匹配且没有质量警告
- `review`：已生成暂算值，但存在估重、缺项暂按 0、替代来源或组成校验等复核提示
- `incomplete`：至少一项食材未匹配或 SOP 解析缺项，结果不能作为完整营养值

## 系统集成

计算核心可独立调用：

```python
from nutrition_tool import calculate_recipe
```

服务契约当前为 `nutrition.calculation.v3`。推荐将自动计算值保存到 `calculated_*` 字段，审核发布值保存到 `published_*` 字段，并记录 SOP、食材数据库及计算规则版本。暂算结果未经营养师审核，不应标记为已发布。
